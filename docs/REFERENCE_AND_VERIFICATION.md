## Invariants established by this change

1. **Projection version, event version and journal identity are distinct.**
   `state_version` is a projection revision. `event_version`/`to_version` are
   positions inside one event journal. `journal_id` identifies the generation.
   A cursor is `(journal_id, version)`.
2. **A journal reset generates a new random id.** `EventJournal.reset()` clears
   retained history, restarts the sequence at 0 and replaces the id. Every new
   Bridge process constructs a new journal and instance id.
3. **Explicit catch-up cannot silently return incomplete history.** An expired
   cursor returns `expired: true`, `resync_required: true`,
   `earliest_available_version`, a typed `resync_from` and
   `history_complete: false`. A foreign cursor returns
   `cursor_status: "journal_mismatch"` and no events. A bare numeric `since`
   remains accepted as a current-journal convenience and is documented as such.
4. **Cursor validation is atomic.** Journal identity, head, earliest retained
   version and the selected batch are read under one condition lock, and the
   response is built from those values.
5. **Reference validity is identity-based, not projection-version-based.**
   `state_version` is advisory metadata on a reference. Staleness is one of
   `ttl`, `identity`, `window`, `bridge_instance`, `unavailable`.
6. **Mutating tools resolve exactly the submitted reference.** They do not
   search for a replacement, fall back to focus, or retry after a stale error.
   A window title supplied as a reference is `4103`, not `4206`.
7. **Verification is derived from an observation.** `verification` is
   `confirmed` only when a post-action projection matches the caller's `expect`;
   `contradicted` when it conflicts; `unavailable` when no read-back exists.
   `dispatched` success alone is never `confirmed`. Evidence is bounded
   (8 entries, 200 characters per text value, 2048 serialized bytes) and
   sensitive paths are redacted.
8. **Errors share one envelope.** Code, name, category, retry policy, details
   and a typed `recovery` are present on every known error. Unknown codes fall
   back to `5303`. Recovery hints never instruct an automatic mutation replay.
9. **Bridge identity is exposed and changes on restart.** `instance_id` is
   32 hex characters generated per construction; `started_at` is ISO-8601 UTC.
   It appears on `/health`, `/tools`, `/state` and every action envelope.
10. **The companion detects replacement.** It sends `journal_id` with event
    polls, honors `resync_required`/`resync_from`, and treats a changed
    `instance_id` in `/tools` as a catalog replacement that invalidates cached
    assumptions.

## Detailed contract notes

### Event journal field compatibility

Existing API-1 fields were kept and extended rather than renamed:

| Field | Meaning |
|---|---|
| `journal_id` | Journal generation |
| `from_version` / `to_version` | Requested cursor / last event in this page |
| `state_version` | Projection revision (kept for existing clients) |
| `event_version` | Journal head |
| `oldest_retained_version` | Old name for the earliest retained version |
| `earliest_available_version` | Same value, clearer name |
| `cursor_status` | `ok`, `paged`, `stale`, `future_cursor`, `journal_mismatch` |
| `expired` | History before the cursor was evicted |
| `resync_required` / `resync_reason` / `resync_from` | Typed recovery |
| `history_complete` | Whether the page is a complete record after the cursor |
| `truncated`, `has_more`, `complete`, `caught_up`, `dropped` | Existing paging facts |
| `cancelled` | Wait ended by shutdown/cancellation |

The tool result also carries `journal_id`, `expired`, `resync_required`,
`resync_reason`, `resync_from`, `history_complete` and `cursor_status`, so a
small model does not have to infer any of them from an empty `events` list.

### Reference identity fields

NVDA-object identity now includes `windowHandle` and `processID` beside role,
name, window class and control id. UIA identity uses control type, automation
id and runtime id. The owning window is compared separately so a replacement is
reported as `window`, not a generic mismatch. `name` is deliberately not
structural: a rename alone does not invalidate a reference.

When no strong field is available (no runtime id, automation id, control id,
window class or handle), identity cannot be verified. The reference is rejected
with `reason_code: "identity"` instead of being used optimistically. This is
deliberately conservative for mutating operations.

### Action result vocabulary

`dispatched` is only meaningful for input dispatch (`press`); it is not forced
onto other results. `observed` means a projection was obtained after the action
and does not establish causality. `uncertain` stays about the consequential
outcome of a dispatched action and is not a synonym for missing evidence.

Actions that take `expect` and run through `Settler` (press, focus, invoke,
navigate, navigate_reading, scroll, dismiss, click_at, activate_window,
set_value, start_browse_mode) report `verification` and `evidence`. `set_value`
overrides the settle-derived verdict with its own platform/UIA/document
read-back and records that source in evidence.

## Deterministic versus simulated

* The tests are deterministic and use fake NVDA objects, fake projections and
  fake clocks. They prove the orchestration, bounds and contract shape.
* No test in this run exercised a real NVDA process, a real UIA provider, a
  real window handle, a real Bridge restart or the installed companion binary.
  Those remain acceptance work, not established guarantees.
* The Rust tests do not open a network listener; HTTP behavior is covered by
  the Python integration test and `httpmock` where present.

## Limitations and assumptions

1. **Live NVDA acceptance was not run.** Object identity, UIA runtime-id
   stability, window-handle reuse and accessibility-tree reads need a real
   session. The identity rules are conservative by design.
2. **No workflow benchmarks were recorded.** Token/round-trip measurements for
   the eight canonical workflows require a live model and NVDA. Do not read the
   payload-size reductions as workflow improvements.
3. **Companion degraded-state model is not a full state machine.** Existing
   behavior is: bounded HTTP timeout, event-poll retry after 1 s, catalog
   refresh on change. A formal `connected/degraded/reconnecting/disconnected/
   shutting_down` surface and a configurable 15 s grace policy remain future
   work; ownership (stdin EOF / parent death) is unchanged and was not
   re-verified in this run.
4. **Window generation token.** The Bridge compares handle, process, class and
   control id. It has no OS-level window-generation token; an improbable
   same-handle/same-process/same-class reuse within the TTL could still pass.
5. **Open-file log semantics** are unchanged; log tools were audited for
   defaults and truncation but not redesigned.
6. **Installed companion version** was not checked against the built source.
   The Rust test result applies to the working tree, not an installed binary.
7. `docs/COMPUTER_USE_REDESIGN.md` was not created: it would describe a
   redesign the current contract does not contain.
