# NVDA MCP Bridge API Reference

Current contract only. This is the first public contract; there are no legacy
levels or aliases.

* Protocol: `nvda-bridge-protocol` `1.0.0`
* API level: `1` (`supported_api_levels: [1]`)
* Bridge / add-on: `0.10.0`
* Transport: HTTP on `127.0.0.1:8765`
* Tool list: `GET /tools`
* Action: `POST /action`

Every request carries `X-NVDA-Bridge-Token`. The token is generated by the
add-on and stored in `%APPDATA%\nvda\nvda-mcp-bridge\token.key`; the companion
reads it when `NVDA_BRIDGE_TOKEN` is unset.

## Discovery

```json
{
  "protocol": "nvda-bridge-protocol",
  "protocol_version": "1.0.0",
  "bridge_version": "0.10.0",
  "api_level": 1,
  "supported_api_levels": [1],
  "schema_hash": "…",
  "types": { "ObserveResult": { "…": "envelope schema" } },
  "tools": [
    {
      "name": "observe",
      "version": "1.0.0",
      "description": "…",
      "category": "observation",
      "inputSchema": { "type": "object", "…": "…" },
      "outputType": "ObserveResult",
      "outputSchema": { "type": "object", "…": "data schema" },
      "readOnly": true
    }
  ],
  "count": 32
}
```

`inputSchema` and `outputSchema` are generated from the same dataclasses used
for runtime validation. `outputSchema` describes the tool's `data` payload, and
the MCP companion returns exactly that object as `structuredContent` (the text
content keeps the envelope metadata).

## Action envelope

```json
{
  "request_id": "…",
  "success": true,
  "action": "observe",
  "duration_ms": 18.2,
  "trace_id": "at-…",
  "bridge": { "bridge_version": "0.10.0", "api_level": 1 },
  "nvda_status_snapshot": {
    "secure_screen": false,
    "modal_blocking": false,
    "menu_open": false
  },
  "result": {
    "ok": true,
    "state_version": 42,
    "changed": true,
    "delta": { "focus": { "from": "…", "to": "…" } },
    "settled_ms": 120.0,
    "uncertain": false,
    "scope": {
      "ref": "w",
      "title": "Notepad",
      "handle": 123456,
      "class_name": "Notepad"
    }
  },
  "data": { "…": "typed tool payload" }
}
```

* `result.state_version` is the version this answer is valid for.
* `result.scope` is the top-level window that scoped the call.
* `result.changed` is a projection diff, not a claim about the whole screen.
* `result.uncertain` is set when the action was dispatched but the effect could
  not be confirmed.
* Failures set `success: false`, omit `data`, and carry `error` with `code`,
  `name`, `message`, `category`, `retry_policy` and optional `details`.

## References and state

`observe` returns `refs` and `top_window`:

```json
{
  "state_version": 42,
  "revision": 7,
  "refs": { "f": "focus", "a1": "ancestor", "d1": "dialog", "w": "window" },
  "focus": {
    "ref": "f",
    "role": "EDIT",
    "name": "Search",
    "value": "bridge",
    "states": ["FOCUSABLE"],
    "location": { "left": 10, "top": 20, "width": 300, "height": 24 }
  },
  "ancestors": [],
  "children": [],
  "dialog": null,
  "top_window": {
    "ref": "w",
    "title": "Notepad",
    "handle": 123456,
    "class_name": "Notepad"
  }
}
```

* A reference is a string matching `^[a-z][a-z0-9]*$`.
* `within` on `locate`/reading tools must be one of those references. A window
  title is rejected with a validation error naming the argument.
* A reference is valid for the `state_version` that produced it. A stale
  reference is `4206` and includes a `recovery` hint; mutating actions are never
  retried automatically.
* `observe` defaults to focus + dialog + top window. `ancestors`, `children`
  and `selection` are opt-in. `detail="summary"` (default) omits states;
  `detail="full"` includes them.

## Tool groups

| Group | Tools |
|---|---|
| Observation | `observe`, `locate`, `read`, `wait_for_events`, `get_action_trace` |
| Reading | `start_browse_mode`, `list_reading_targets`, `navigate_reading` |
| Action | `invoke`, `set_value`, `focus`, `press`, `navigate`, `scroll`, `dismiss`, `click_at`, `activate_window` |
| Inspection | `inspect_object`, `inspect_app_module`, `walk_object_tree`, `get_focus_lineage`, `list_loaded_addons`, `health_snapshot` |
| Logs | `get_logs`, `search_logs`, `get_log_context`, `summarize_logs` |
| System | `restart_nvda`, `reload_plugins`, `execute_python`, `speak_text`, `show_message` |

### Defaults that matter

* `wait_for_events(since=None)` starts at the current `state_version`; pass
  `since=0` to read history.
* `health_snapshot()` returns status, focus/window and errors. Add-on names and
  logs are opt-in with `include_addons` / `include_logs`.
* `locate(detail="summary")` omits `path`, `depth`, `automation_id` and `states`.
* `get_logs` defaults to 100 lines; `search_logs` defaults to 20 records.
* `press` accepts `ctrl`, `win`, `esc`, `return`, `pgup`, `pgdn` and
  `up`/`down`/`left`/`right`; the result reports `requested` and
  `normalized_keys`.

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/tools` | Tool catalog (`?category=` filters) |
| `POST` | `/action` | Execute one tool |
| `GET` | `/state` | Current projection (no refs; read-only) |
| `GET` | `/events?since=&limit=` | Event journal page |
| `GET` | `/health` | Liveness and NVDA status |

## Error codes

| Code | Name | Meaning |
|---:|---|---|
| 4001 | `AUTH_FAILURE` | Missing/wrong token |
| 4003 | `PERMISSION_DENIED` | Capability not granted |
| 4101 | `INVALID_JSON` | Malformed request body |
| 4102 | `INVALID_ACTION_NAME` | Unknown tool |
| 4103 | `INVALID_PARAMS_SCHEMA` | Input does not match `inputSchema` |
| 4201 | `SECURE_SCREEN_ACTIVE` | Secure desktop is active |
| 4202 | `MODAL_DIALOG_BLOCKING` | Modal dialog blocks the action |
| 4203 | `MENU_OPEN_BLOCKING` | NVDA menu is open |
| 4204 | `ACTION_CANCELLED` | Caller cancelled |
| 4205 | `TARGET_UNAVAILABLE` | Object cannot be acted on |
| 4206 | `STALE_REFERENCE` | Reference expired; observe again |
| 5001 | `NVDA_COM_TIMEOUT` | COMVoice/UIA timed out |
| 5004 | `ACTION_TIMEOUT` | Budget expired |
| 5303 | `INTERNAL_ERROR` | Unclassified bridge failure |

A `4103` includes the field path and expected shape. A `4206` includes
`details.ref`, `details.reason` and `details.recovery`.

## Safety

* Deny-by-default capabilities; elevated tools require an explicit grant.
* Actions are blocked on the secure desktop, and restricted while a modal or the
  NVDA menu is open.
* `execute_python` and lifecycle tools are developer/opt-in operations.
* The bridge binds loopback only and validates the token before parsing input.
